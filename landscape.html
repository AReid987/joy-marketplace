A wrapper is not an agent business.

Agent directories hollow out. Generic harnesses are being bundled by platforms with models, distribution, trust, memory, tools and payment rails. The surviving marketplaces do one thing the wrappers do not: they move work and money.

01 / CATEGORY ERROR

“Agent” is not one product.

It can mean a model, a prompt-and-tool loop, a hosted runtime, a reusable skill, an autonomous worker, a UI, or a store listing. Calling all of them “assets” hides the hard question: what is being sold, to whom, and why will they pay?

The thin definition

A model plus a workflow canvas plus an upload/deploy action. This is easy to demo, but it competes with free open-source orchestration and bundled platform features.

The useful definition

An accountable worker: it remembers, chooses tools and models, acts in real systems, can be evaluated, observed, paid, governed and improved. That is a stack—not a screen.

05 / MCP TRUST DEBT

USB for agents—without USB’s trust boundary.

MCP connects models to tools, but tool descriptions are free text placed directly in the model’s context. That gives documentation the power to behave like instructions.

01

Poisoned descriptions

A malicious server hides orders in documentation the model must read.

02

Confused deputy

The poison can hijack another trusted tool; the malicious tool need not run.

03

Late auth

The original Nov 2024 spec shipped with no authentication model.

04

Rug pulls

A benign tool definition can change after approval without mandatory re-approval.

05

Command execution

Unsafe STDIO defaults spread command injection across implementations.

APR 2025

Invariant Labs demonstrated SSH-key theft and WhatsApp hijacking through tool poisoning. The malicious tool was never invoked.

2025

MCP Inspector exposed remote code execution by binding to all interfaces without authentication. Multiple RCE-class CVEs followed.

JAN 2026

MCPTox induced an attacker-selected tool call in up to 84.2% of prompts across 12 model/agent settings; it measured selection, not confirmed production side effects.

APR 2026

OX Security reported a systemic STDIO design flaw across four official SDK bindings and ten derived CVEs; reported blast radius: 7,000+ public servers and 150M+ package downloads.

JUL 2026

The spec hardened remote auth with OAuth 2.1 + PKCE and related protections. Adoption across public servers was still catching up; free-text tool descriptions remain.

06 / LICENSE REALITY

n8n is source-available. It is not open source.

Its Sustainable Use License permits internal business use, but it was explicitly designed to stop a company from wrapping n8n and selling the wrapper as a competing hosted product.

Free under SUL

Self-host n8n for internal company automations. Build workflows for clients as a consultant or agency. Use it personally or non-commercially.

Commercial license required

Embed n8n as a feature in a paid product, resell hosted n8n, or brand its canvas as the customer-facing core of a commercial platform.

This is an interpretation of public license text, not legal advice. Confirm the current Enterprise/Embed terms with n8n and counsel before shipping.

07 / RECOMMENDATION

Do not raise to discover the product.

The current category is too broad to support a clear buyer, a credible moat or a capital plan. The next step is not more surface area. It is a short, instrumented market test.

Run two offers

  • Choose one specific buyer with an urgent, expensive workflow.
  • Define two narrow offers with measurable outcomes.
  • Ship each as a simple web product or concierge service—not an OS.
  • Measure qualified conversations, activation, completion, repeat use and willingness to pay.
  • Keep the winner; kill or revise the loser.

Only then fund the moat

  • Vertical workflow depth
  • Proprietary data and memory
  • Governance and verified execution
  • Payment, escrow or settlement
  • Distribution into a real buyer channel

The defensible sentence

“We solve this costly job for this buyer, with this evidence, and every completed job compounds our data, trust or payment advantage.”

RUNTIME LEARNING

Adapt first. Fine-tune only when justified.

The default is shifting from “retrain the model” toward memory, retrieval and test-time loops that learn during use. Fine-tuning remains useful for small models, stable style and low-latency deterministic outputs.

AttemptGenerate a candidate action
VerifyCheck with tests or tools
ReviseUse the failure signal
RememberStore what worked
ImproveReuse on the next job

What changes

Context engineering, memory and verification loops become product infrastructure. The learning layer often lives outside the model weights.

What does not disappear

PEFT/LoRA and distillation still matter for smaller models, latency, controlled tone and repetitive outputs. “Agents learn” is a shift in default—not the death of MLOps.
